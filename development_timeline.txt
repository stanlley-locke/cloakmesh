PHASE 0: FOUNDATION & WORKSPACE INITIALIZATION
================================================================================
Goal: Establish a clean, reproducible, polyglot development environment.

Steps:
  0.1  Install prerequisites
       - Rust: curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
       - Python 3.10+: sudo apt install python3 python3-pip python3-venv
       - Poetry: curl -sSL https://install.python-poetry.org | python3 -
       - Node.js 18+: curl -fsSL https://deb.nodesource.com/setup_18.x | sudo bash && sudo apt install nodejs
       - protoc: sudo apt install protobuf-compiler
       - just: curl --proto '=https' --tlsv1.2 -sSf https://just.systems/install.sh | bash -s -- --to /usr/local/bin
       - Docker & Docker Compose

  0.2  Initialize project root & version control
       - mkdir cloakmesh && cd cloakmesh
       - git init
       - Add .gitignore (target/, .venv/, node_modules/, *.egg-info, .env, dist/)

  0.3  Configure Rust workspace
       - Create root Cargo.toml with [workspace] members = ["core", "wasm"]
       - Create core/ and wasm/ directories with cargo new --lib

  0.4  Configure Python orchestrator
       - mkdir -p orchestrator/src/cloakcli orchestrator/tests
       - poetry init (non-interactive, set name/version/dependencies)
       - Add pyproject.toml scripts: cloakcli = "cloakcli.main:app"

  0.5  Configure TypeScript SDK
       - mkdir -p sdk/src sdk/examples sdk/tests
       - npm init -y
       - Install dev deps: typescript, ts-node, jest, eslint, prettier

  0.6  Initialize tooling & CI skeleton
       - Add rustfmt.toml, .cargo/config.toml, .editorconfig
       - Create .github/workflows/ci.yml (placeholder)
       - Create Justfile with empty targets

Checkpoint:
  ✅ just install-deps succeeds
  ✅ cargo build, poetry install, npm install run cleanly
  ✅ git status shows clean workspace
Dependency: None (First phase)

PHASE 1: PROTOCOL DEFINITION & CROSS-LANGUAGE BINDINGS
================================================================================
Goal: Establish the single source of truth for network messages and generate bindings.

Steps:
  1.1  Draft core protobuf schemas in proto/v1/
       - cloakmesh.proto (Handshake, Ping, StreamData, PeerIdentity, Envelope)
       - cloak_service.proto (Descriptor, Introduce, Rendezvous, Capability)
       - dht.proto (Store, Fetch, VerifyProof)
       - telemetry.proto (Metrics, Health, LogStream)
       - traffic.proto (Cell, PaddingConfig, CoverFlow)

  1.2  Set up codegen pipeline
       - proto/generate.sh: protoc calls for Rust (tonic-build), Python (grpcio-tools), TS (@grpc/proto-loader + grpc-web)
       - Update core/build.rs to invoke tonic_build::compile_protos()

  1.3  Generate & validate bindings
       - Run just proto-gen
       - Verify generated files exist in core/src/, orchestrator/src/proto/, sdk/src/proto/
       - Write minimal smoke tests importing generated types in each language

  1.4  Establish versioning strategy
       - Add version field to all proto messages
       - Document backward/forward compatibility rules in proto/README.md

Checkpoint:
  ✅ All .proto files compile without errors
  ✅ Generated code loads in Rust, Python, TS
  ✅ Cross-type parity validated (same field names, types, enums)
Dependency: Phase 0

PHASE 2: RUST CORE ENGINE (NETWORK, CRYPTO, CLOAK PROTOCOL)
================================================================================
Goal: Implement the secure, high-performance backbone of CloakMesh.

Steps:
  2.1  Cryptography Module (core/src/crypto/)
       - Ed25519 keypair generation, signing, verification
       - X25519 ECDH key exchange
       - Kyber-768 hybrid PQ wrapper (use libcrux or pqcrypto)
       - Noise protocol handshake (XX pattern, ChaChaPoly, BLAKE2s)
       - Session key derivation & rotation logic
       - ZK proof stub interface (trait-based, mock for now)

  2.2  Network & Transport Layer (core/src/network/)
       - QUIC & TCP transport adapters
       - NAT traversal helpers (STUN/UPnP, port mapping, hole punching)
       - libp2p bridge for peer discovery & connection pooling
       - Stream multiplexing (mplex/yamux)
       - Connection lifecycle & heartbeat

  2.3  Routing & DHT (core/src/routing/)
       - Kademlia routing table (XOR distance, k-buckets, refresh)
       - GossipSub integration for pub/sub messages
       - Adaptive circuit builder (2-5 hops, threat-model config)
       - Rendezvous point selector & cookie manager
       - Reputation scoring system (latency, uptime, behavior)

  2.4  Cloak Protocol Implementation (core/src/cloak_protocol/)
       - .cloak address parser & validator (base32 + Bech32 checksum)
       - Descriptor assembler & Merkle root computation
       - Signed descriptor verification (Ed25519 + timestamp/nonce)
       - Introduce flow (INTRODUCE1/2, cookie relay, capability validation)
       - Traffic padding engine (fixed cells, jitter, cover flow scheduler)

  2.5  Storage & Telemetry (core/src/storage/, core/src/telemetry/)
       - In-memory KV cache with TTL for descriptors/sessions
       - Write-ahead journal for crash recovery
       - Prometheus metrics exporter
       - Tracing integration (env-filter, structured logs)

  2.6  Node Entrypoint & CLI (core/src/main.rs, core/src/config.rs)
       - Parse TOML config & CLI args
       - Initialize crypto identity
       - Spawn tokio runtime, bind gRPC + QUIC listeners
       - Graceful shutdown handling (SIGTERM, drain connections)

  2.7  Core Testing (core/tests/)
       - Unit tests for crypto, address parsing, padding
       - Integration tests: local 3-node handshake & stream
       - Fuzzing targets (proto deserialization, address decode)

Checkpoint:
  ✅ Core compiles with --release, zero warnings
  ✅ Local test: 3 nodes discover, handshake, stream data
  ✅ All core tests pass, coverage >70%
Dependency: Phase 1

Steps:

  3.3  Build & test in browser
       - Run wasm-pack build --target web
       - Create wasm/web/index.html + worker.js
       - Test session creation, descriptor fetch, message send/receive

Checkpoint:
  ✅ wasm-pack builds successfully
  ✅ Browser console loads module, runs crypto ops

PHASE 6: SECURITY HARDENING & COMPREHENSIVE TESTING
================================================================================
Goal: Validate security guarantees, fix vulnerabilities, and optimize performance.

Steps:
  6.1  Static & Dependency Auditing
       - cargo audit, cargo-udeps, clippy -- -D warnings
       - npm audit, poetry check, pip-audit
       - Snyk/Dependabot integration

  6.2  Fuzzing & Property Testing
       - cargo-fuzz for proto deserialization, address parsing
       - Hypothesis (Python) for session state machine
       - TS fast-check for capability token generation

  6.3  Threat Model Validation
       - Traffic correlation test: run mitmproxy + Wireshark, verify fixed cells
       - Replay attack simulation: duplicate envelopes, verify nonce/timestamp rejection
       - Descriptor poisoning test: inject fake Merkle roots, verify DHT client rejects
       - Sybil resistance test: spawn 50 low-rep nodes, verify routing ignores them

  6.4  Performance & Load Testing
       - k6 scripts for concurrent sessions, descriptor fetches, RP connections
       - Benchmark crypto ops, DHT lookups, padding overhead
       - Optimize hot paths (zero-copy buffers, async batching, connection pooling)

Checkpoint:
  ✅ Zero critical/high audit findings
  ✅ Fuzzing runs 100k+ iterations without crashes
  ✅ Load test handles 5k concurrent sessions with <5% packet loss
  ✅ Traffic analysis shows no plaintext/metadata leaks
Dependency: Phases 2-5

FINAL NOTES & BEST PRACTICES
================================================================================
- Always run just lint && just test before committing
- Never merge proto changes without regenerating all bindings
- Keep cryptography isolated; never trust unvalidated network input
- Use structured logging; avoid PII in telemetry
- Rotate keys & certificates regularly; automate where possible
- Document threat model updates with every protocol change
- Prioritize user sovereignty: no telemetry without explicit opt-in
